# 鹈鹕骑自行车 / Lab 4

[English instructions: README.md](README.md)

**三个人合作，在同一个场景里各增加一种交互。** 自行车场景已经做好了。你只需让自己的 AI Agent 添加一个控件，然后把三个人的文件合起来试玩。这是一个完整的小组练习，不计分、不需要提交。

## 第 1 步：打开看看
1. 把整个 ZIP 解压到普通本地文件夹，不要在压缩包预览里打开。
2. 双击 `reference.html`，试试成品的速度、角色和视角切换。
3. 打开 `index.html`。鹈鹕已经会骑车，下方三个交互控件由你们小组完成。

**这个项目本身**不需要安装 Node、Python、npm、服务器或配置 API key。你的 Agent 工具可能需要自己的账号与网络。如果双击后打开的是编辑器，请选择“使用浏览器打开”。保留文件夹内所有文件。

## 第 2 步：分工，选一种协作方式

| 成员 | 添加的交互 | Agent 只修改这个文件 |
|---|---|---|
| A | 0–3 倍速度滑块 | `features/speed.js` |
| B | 鹈鹕 / 鸭子 / 企鹅切换 | `features/character.js` |
| C | 全景 / 近景 / 跟随视角切换 | `features/view.js` |

从三人中选一位负责整合。每个人使用自己的本地副本，可以用不同的 AI Agent。

**文件交接**最容易开始：三人分别解压同一份起始包，完成后把自己的功能文件发给整合者。如果小组已经能使用仓库，也可以选择 **GitHub 或 Gitee**。修改之前让 Agent 阅读 `docs/PLATFORMS.md`，带你建立同一仓库的副本和分支。全组选同一平台。一人建立共享仓库并邀请另两位成员，每人克隆到自己的本地文件夹，再建立自己的分支。账号、网络或安装卡住时，直接改用文件交接。

## 做你们自己的版本

不要原封不动复制 reference/ 里的功能代码，也不要照搬参考控件的样式。写代码前，先选一个小的设计差异，例如在速度滑块旁增加快捷档位、用按钮组切换角色、用带说明的下拉框选择视角，再让 Agent 按需求独立实现。现成的自行车场景、公共接口和函数签名可以直接复用，不需要重新画图，也不要求刻意把正常的 JavaScript 语法写得不一样。仅把复制代码的变量名或颜色改掉，不算独立实现。

## 第 3 步：让 Agent 完成自己的控件

在 Agent 中打开整个项目文件夹。复制下面的话，把角色改成自己负责的字母：

> 请阅读 README_ZH.md 和 AGENTS.md。我是成员 [A/B/C]，请按第 3 步实现我的角色。只改我的功能文件，调用已有 ride 接口。保持简单，直接打开 index.html 就能运行。不要改公共代码和队友的文件。请先让我选择一个小的设计差异，再按需求独立实现。不要复制参考功能代码，也不要照搬参考控件样式。完成后测试你能测试的内容，明确告诉我实际测过什么，并给我一段交接说明。

**A：速度**
- 在 features/speed.js 中保留 `window.mountA(root, ride)`。
- 添加带标签的滑块，最小值 0，最大值 3，步长 0.1。
- 拖动时调用 `ride.setSpeed(value)`，显示当前倍速。
- 检查 0 能停止，3 比 1 更快。

**B：角色**
- 在 features/character.js 中保留 `window.mountB(root, ride)`。
- 添加下拉框或按钮，选项值为 `pelican`、`duck`、`penguin`。
- 选择后调用 `ride.setCharacter(name)`。三种角色的图形已经做好。
- 检查三种角色都能出现，同时保留当前速度和视角。

**C：视角**
- 在 features/view.js 中保留 `window.mountC(root, ride)`。
- 添加按钮或下拉框，选项值为 `wide`、`close`、`follow`。
- 选择后调用 `ride.setView(name)`，标明当前选中的视角。
- 全景展示海边路线，近景突出骑手，跟随视角保持自行车在画面中、让沿途景物从背后经过。镜头过渡已由公共代码实现。
- 检查三种取景效果，同时保留当前角色和速度。
- 这里是二维画面的取景变化，不用学习三维建模。

三位成员都要从 `ride.getState()` 读取状态，注册一次 `ride.subscribe(render)`，保证点击 Reset scene 时控件也能更新。不要在 render 中再次调用 setter，否则会循环。具体接口在 `docs/API.md`，让 Agent 阅读即可。控件也应支持键盘操作。

## 第 4 步：试试自己的功能

保存后刷新 `index.html`。队友没完成的控件仍显示文字是正常的。先测试自己的功能。如果失败，告诉 Agent：你做了什么、希望看到什么、实际发生了什么。例如：“我选择 Duck 后角色没有变化，请只修复 features/character.js。”

你不需要自己读懂或修改代码，但要确认页面行为，并检查 Agent 列出的修改文件。参考版本只是一个例子，可以有自己的设计。模型卡住时，让它解释相关概念，再回到需求实现最小可用版本，不要把参考答案粘贴进自己的功能文件。

## 第 5 步：让 Agent 帮你们整合

文件交接：每个人只发送自己的功能文件，再附一句“做了什么、测过什么”。整合者使用一个单独的起始项目副本，先备份，再依次放入三个文件。保留 speed.js、character.js、view.js 这三个文件名，不要拿自己的整个文件夹覆盖队友的项目。

整合者可复制：
> 请阅读 docs/INTEGRATE.md。我们已经有三份功能文件，请先帮我备份整合文件夹，核对收到的文件，只把约定的三个文件放到 features/。不要改公共代码。整合完成后带我们做 README_ZH.md 的第 6 步，明确报告缺失的文件和没有通过的检查。

GitHub/Gitee：让 Agent 帮你把功能提交、推送到自己的分支，在网页创建合入默认分支的 Pull Request。队友先检查，整合者再合并三份贡献，并拉取到本地。之后每个人都更新自己的本地默认分支。合并后的主分支就是同一项目的新版本，不用另建仓库。`docs/PLATFORMS.md` 提供一步步的 Agent 提示词。账号登录由你本人完成。

## 第 6 步：一起试玩

在整合者电脑打开**合并后的** `index.html`：
1. 把速度设为 2。
2. 把角色切换成 Duck。
3. 把视角切换成 Close。
4. 三个选择应该同时保持生效。
5. 把速度设为 0，车轮、脚踏、路面和镜头运动都应停止。
6. 点击 Reset scene，恢复鹈鹕和 Wide，所有控件与场景状态一致。

让一位队友独立操作，其他人先别提示。发现问题后找对应成员的 Agent 修复。三个控件能一起工作，这个练习就完成了。刷新页面会重置场景。我们合并的是代码，不是跨电脑实时同步场景状态。

## 做完后才尝试的自由发挥

可以改变控件样式、显示标签，或者提出一个小交互。先商量谁负责、要改哪个文件。这个练习中保持已有公共接口不变。

## 卡住时怎么办
- Git 安装不了或平台打不开：改用文件交接。
- 页面空白：确认已完整解压，用浏览器打开 index.html，让 Agent 检查控制台报错。
- 修改没出现：确认保存了正确文件，刷新正确文件夹里的 index.html。reference.html 始终显示参考答案。
- Agent 要安装框架：告诉它“使用已有本地 HTML 和原生 JavaScript，遵守 AGENTS.md，不需要安装”。
- 一开始不动：系统可能开启了减少动态效果，主动调节速度即可开始。
